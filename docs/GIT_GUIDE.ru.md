# Git и GitHub для QuizForge — короткая инструкция

## Что есть сейчас

В папке `Individual_Project/QuizForge` уже создан Git-репозиторий. На момент подготовки этой инструкции коммитов ещё нет и GitHub remote не подключён. Создание `.git` и установка зависимостей сами по себе не создают коммит.

- **Git** хранит историю изменений локально.
- **Коммит** — сохранённая версия выбранных файлов с сообщением о реальном изменении.
- **GitHub** — удалённый репозиторий, куда отправляется эта история.
- **Push** — отправка локальных коммитов в GitHub.

## Когда делать коммиты

По PDF нужно не менее **8 осмысленных коммитов в разные дни**. История и ссылка на GitHub должны быть готовы к финальной сдаче проекта.

- После сообщения в обсуждении API choice продолжать разработку и коммиты нормально.
- После сдачи proposal продолжать разработку и коммиты тоже нормально.
- К финальной сдаче GitHub и ZIP должны соответствовать одной сдаваемой версии. На коммиты после финальной сдачи нельзя рассчитывать как на выполнение требования без отдельного разрешения преподавателя.
- Если сдаёшь или защищаешь проект раньше, согласуй с преподавателем дату фиксации версии и требования к истории. Когда времени на разные дни уже нет, уточни условие заранее.

Восемь коммитов за один вечер не выполняют условие «в разные дни». Даты должны отражать реальную работу. Уже подготовленную исходную версию можно сохранить одним честным стартовым коммитом, а дальше фиксировать реальные улучшения, исправления и свои проверенные материалы по мере работы.

## 2. Посмотри, что изменилось

```sh
git status
git diff
git log --oneline -10
```

До первого коммита `git log` сообщит, что коммитов ещё нет: это ожидаемо. Новые неотслеживаемые файлы `git diff` пока не показывает; просмотри их в редакторе.

Проверь исключения:

```sh
git check-ignore .env node_modules
```

Обе строки должны появиться в выводе. `.env.example`, наоборот, должен попасть в репозиторий: там только пример настроек.

## 3. Создай первый коммит, когда просмотрел исходную версию

Добавь только файлы этого проекта:

```sh
git add .gitignore .env.example package.json package-lock.json app.js README.md routes controllers services middleware utils views public test docs
git diff --cached --stat
git diff --cached
git status
```

В списке не должно быть `.env`, `node_modules` или секретного значения `SESSION_SECRET`. Убедись, что понимаешь, какие файлы сохраняешь. Затем:

```sh
git commit -m "Add QuizForge application"
```

Если Git выдаст `Author identity unknown`, коммит ещё не создан. Сохрани сообщение ошибки и обратись за помощью с настройкой своего настоящего имени и email.

## 4. Подключи GitHub

Создай на GitHub пустой репозиторий `quizforge`. Готовые README и .gitignore уже есть локально, поэтому при создании удалённого репозитория оставь эти дополнительные файлы выключенными.

Подставь свой реальный URL вместо примера:

```sh
git remote add origin https://github.com/YOUR_USERNAME/quizforge.git
git remote -v
git push -u origin HEAD
```

Git может предложить авторизацию через браузер. Если репозиторий приватный, предоставь преподавателю доступ. `remote add` выполняется один раз; для уже подключённого репозитория достаточно проверить `git remote -v`.

## 5. Как делать следующие коммиты

Сначала внеси реальное изменение и проверь его. Например, если ты самостоятельно улучшил пояснения на странице About:

```sh
git status
git diff
git add views/about.ejs
git diff --cached
git commit -m "Clarify quiz instructions on About page"
git push
```

В `git add` указывай именно изменённые тобой файлы. Если ты исправил серверную логику, запусти `npm test` перед коммитом. Для изменений интерфейса также проверь страницу в браузере.

Сообщение должно объяснять, что действительно изменилось: `Improve mobile answer layout`, `Handle an additional API error`, `Document completed manual checks` — только когда соответствующая работа выполнена.

Необязательно создавать коммит каждый день без изменений. Но для выполнения условия задания планируй настоящую работу в разные дни до финальной сдачи.

## 6. Что проверить перед финалом

```sh
git status
git log --format="%h %ad %s" --date=short
git remote -v
```

Проверь минимум 8 осмысленных коммитов в разные дни, наличие этих коммитов на GitHub и доступ преподавателя. Подготовь ZIP из той же версии исходников, исключив `.env` и `node_modules`. Архивирование — отдельный этап перед финальной сдачей.
