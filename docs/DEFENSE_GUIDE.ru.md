# QuizForge: как разобраться и подготовиться к защите

## Короткое описание проекта

«QuizForge позволяет выбрать тему, сложность и количество вопросов. Сервер получает категории и вопросы из Open Trivia DB через Axios. EJS создаёт HTML-страницы. Правильные ответы остаются в серверной сессии. После отправки формы сервер проверяет выбранные варианты, считает баллы и показывает разбор».

## В каком порядке читать код

1. `app.js` — подключение Express, статических файлов, EJS, парсера формы, сессии и маршрутов.
2. `routes/quiz-routes.js` — какой URL вызывает какой контроллер.
3. `controllers/quiz-controller.js` — основной сценарий пользователя.
4. `services/trivia-service.js` — два запроса к API, кеш, обработка его ошибок.
5. `utils/quiz.js` — перемешивание, подготовка вопросов, проверка ответов и оценка.
6. `middleware/validate-settings.js` — проверка данных формы до запроса вопросов.
7. `views/` — HTML, циклы EJS и условия.
8. `middleware/error-handler.js` — понятные пользователю страницы ошибок.

## Путь одного запроса

### Открытие главной

`GET /` → контроллер `home` → `getCategories()` → Axios → список категорий → EJS `home.ejs`.

Категории сортируются по имени и кешируются на шесть часов. Кеш — переменная в памяти процесса, а не база данных.

### Начало квиза

Форма отправляет `POST /quiz` с `category`, `difficulty` и `amount`.

1. `express.urlencoded` превращает тело HTML-формы в `req.body`.
2. `validateSettings` проверяет строки, допустимые сложности и количество 5/10.
3. Контроллер дополнительно убеждается, что ID есть в списке категорий API.
4. `getQuestions()` передаёт выбранные значения в Axios `params`.
5. `buildQuiz()` перемешивает варианты и создаёт случайный ID раунда.
6. В `req.session.quiz` остаётся полный квиз с правильными ответами.
7. `publicQuiz()` убирает правильные ID из данных, передаваемых странице вопросов.
8. `res.render('quiz', ...)` создаёт HTML через EJS.

### Отправка ответов

`POST /results` → проверка ID текущего раунда → `readAnswers()` → `gradeQuiz()` → сохранение результата → `res.redirect(303, '/results')`.

Браузер затем делает `GET /results`. Обновление этой страницы не отправляет ответы повторно. Повторная отправка того же завершённого раунда открывает сохранённый результат. Старый раунд, заменённый новым, отклоняется.

## Ключевые понятия

**Маршрут** связывает HTTP-метод и URL с обработчиком. `GET /results` показывает результат, а `POST /results` проверяет ответы: одинаковый путь, разные действия.

**Контроллер** координирует проверку ввода, работу сервиса и выбор представления. Axios находится в сервисе, чтобы не смешивать внешний API с HTML и маршрутизацией.

**Middleware** выполняется в цепочке обработки запроса. `next()` передаёт управление дальше, `next(error)` — обработчику ошибок. Свой логгер записывает метод, URL, время и статус ответа. Обработчик ошибок имеет четыре аргумента `(error, req, res, next)`.

**Сессия** хранит данные пользователя на сервере. В браузерной cookie находится подписанный идентификатор сессии, а не вопросы и правильные ответы. В этой учебной версии память очищается при перезапуске сервера. Сессия приложения не является API-ключом или токеном OpenTDB.

**async/await** позволяет дождаться HTTP-ответа в асинхронной функции. Пока Axios ждёт сеть, Node.js может обрабатывать другую работу. `try/catch` перехватывает отклонённый запрос и передаёт понятную ошибку дальше.

**Axios params** безопасно формирует параметры URL. При «All topics» или «Mixed» соответствующий параметр опускается. Тип вопросов всегда `multiple`.

**Кодировка:** API запрашивается с `encode=url3986`, затем строки декодируются через `decodeURIComponent`. Декодирование и HTML-экранирование — разные действия. В EJS `<%= текст %>` экранирует данные, а `<%- include(...) %>` вставляет наш готовый HTML partial.

**Обработка ответа:** успешный HTTP 200 ещё не означает успешный квиз. Нужно проверить `response_code`: 0 — успех, 1 — недостаточно вопросов, 5 — ограничение частоты. Также проверяем структуру и количество вопросов.

## Алгоритмы, которые нужно уметь объяснить

### Перемешивание Fisher–Yates

Идём с конца массива. На каждом шаге выбираем случайный индекс от 0 до текущего и меняем два элемента местами. Работаем с копией массива. Вместе с текстом временно хранится флаг правильного варианта, поэтому после перемешивания правильный ID остаётся известен серверу.

### Проверка ответов

Каждый вопрос имеет ID `q0`, `q1` и т. д.; варианты — `a0`–`a3`. Форма отправляет, например, `answer_q0=a2`. Проверяем, что значение является строкой и существует среди вариантов именно этого вопроса. Пропущенный или выдуманный ID не засчитывается: форма снова показывается с подсказкой.

### Оценка

Сравниваем выбранный ID с правильным у каждого вопроса. Считаем совпадения через `filter`, затем:

```js
Math.round((correct / total) * 100)
```

Пример: 3 правильных из 5 → 60%. Сначала проверяем порог 80%, затем 50%, затем оставшийся случай, чтобы выбрать звание.

## План демонстрации на 5–7 минут

1. **До 1 минуты:** задача приложения, технологии и источник данных.
2. **1 минута:** выбрать категорию, сложность и 5 вопросов; показать форму и оба запроса API в сервисе.
3. **1–2 минуты:** ответить на вопросы, показать прогресс, результат и разбор.
4. **1 минута:** показать папки MVC, middleware, серверную сессию и формулу оценки.
5. **1 минута:** открыть неизвестный URL, объяснить валидацию и дружелюбную обработку ошибок API; показать `npm test`.

Перед демонстрацией проверь интернет. Между запросами нового раунда выдерживай не менее 6 секунд: это ограничение API, а не зависание сайта.

## Небольшие изменения для тренировки

- Поменять акцентный цвет `--accent` в `public/css/styles.css`.
- Изменить подписи или границы званий в `gradeQuiz()` и поправить соответствующий тест.
- Добавить количество 15 в `views/home.ejs` и допустимый список в `middleware/validate-settings.js`.
- Изменить порядок категорий в `getCategories()` и перезапустить сервер, чтобы очистить кеш.
- Добавить вывод сложности к каждому вопросу в разборе результатов.

Сначала попробуй сделать эти правки самостоятельно и объяснить, почему нужны именно эти файлы. На защите AI использовать нельзя.
